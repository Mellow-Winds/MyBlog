# MyBlog Alpha Plan

> 日期：2026-09-12  
> 阶段：Alpha 规划  
> 目标：构建一个可由 GitHub Pages 直接托管的个人主页静态网站。  
> 规划起点：先完成仓库初始化、设计调研和计划；后续实现按用户确认的范围逐步推进。

## 1. 已确认需求

### 1.1 产品目标

构建一个个人主页静态网站，最终可以直接放入 GitHub 仓库并由 GitHub Pages 托管。网站不依赖后端、数据库或必须运行的服务器；访客只需要浏览器即可查看内容。

### 1.2 视觉目标

网站采用左右双栏布局，视觉设计语言完全参考工作区内的 `MD_Demo`。这里的“参考”指颜色、排版、空间、圆角、表面层级、交互状态和响应式方式保持同一设计系统；信息架构仍以本项目的个人主页需求为准，不复制 `MD_Demo` 的设计展厅页面。

### 1.3 首期板块

1. 关于我
2. 学在南雍
3. 玩在金陵
4. 南雍杂忆
5. 文章检索
6. GitHub

所有功能性图标和装饰性图标均使用 SVG。不得使用 emoji、图标字体或风格不一致的外部图标集替代 SVG；纯图标按钮必须有可访问名称。

## 3. MD_Demo 设计细则审计结论

### 3.1 视觉北极星

沿用“清晰、清爽、圆润、克制；每一次交互都有可预测反馈”的气质。内容层级由标题、正文、辅助文字和边界建立，不用大段标签、编号或装饰数字制造层级。

### 3.2 颜色合同

默认主题严格使用四个基础色，并通过透明度混合表达次级状态：

```css
--primary: #4A90D9;
--container: #D3E4FD;
--surface: #F9F9FF;
--ink: #1A1B21;
```

实施要求：

- 交互蓝用于主操作、选中态和焦点；容器蓝用于选中背景和强调容器。
- 画布白承载主要内容；文字墨用于正文、轮廓和遮罩。
- 通过 `color-mix()` 或透明度形成 `outline`、`muted`、`soft`、`hover` 等衍生 Token，不另开红、绿、橙等语义色。
- 主按钮使用深色主操作底并配浅色文字，先检查普通文本对比度至少 4.5:1。
- 当前 Alpha 骨架按用户确认使用液态玻璃；渐变只存在于底层背景，表面使用透明度、模糊、高光和阴影表达层级。Windows 透明效果开关不影响材质；高对比度、强制配色或浏览器不支持模糊时，自动使用实体回退。

### 3.3 版式与空间合同

- 桌面端 `body` 使用 `240px minmax(0, 1fr)` 的左右双栏；左栏稳定，右侧主内容独立滚动。
- 主内容设置合理的最大宽度和响应式内边距，避免大屏内容无限拉宽。
- 采用 4px 基础网格，优先使用 4、8、12、16、24、32、48、64px 间距 Token，禁止随意出现无法解释的魔法数字。
- 网格子项必须允许收缩，代码或长文本只能在自己的容器内滚动，不能撑开整页。
- 默认卡片约 20px 圆角，展示容器约 24px 圆角，输入框约 8px 圆角，菜单约 12px 圆角，按钮和标签切换使用胶囊形。
- 卡片只在需要时使用弱边框或单一层级阴影，不为所有元素堆叠阴影。

### 3.4 文字合同

- 字号沿用 12 / 14 / 16 / 20 / 24 / 32px 体系；大屏主视觉最多扩展至 40px，移动端页面标题收敛至 28px。
- 优先系统中文无衬线字体；正文常规字重，标题和当前操作使用中等或半粗字重。
- 标题回答“是什么”，正文回答“为什么”，操作文案直接说明动作。
- 个人经历、学校经历、地点和文章内容必须由用户提供或由已有资料核验，不得用虚构事实填充。

### 3.5 图标合同

- 使用统一的线性 SVG 图形，导航图标目标尺寸 24px，按钮图标目标尺寸 20px。
- 图标通过内联 SVG 或本地 SVG symbol sprite 管理，确保 GitHub Pages 离线部署时不依赖外部图标 CDN。
- 头像、封面等未来内容图片与功能图标区分处理；在用户未提供素材前，使用结构占位，不生成貌似真实的个人信息。
- 图标按钮必须有 `aria-label`；装饰图标设置 `aria-hidden="true"`。

### 3.6 状态、动效和可访问性

- 控件实现默认、悬停、聚焦、按下、禁用、选中和异常等必要状态；状态不能只依赖颜色。
- 焦点使用清晰的可见轮廓；可点击目标至少接近 44px 高度。
- 尊重 `prefers-reduced-motion: reduce`，减少或移除非必要位移和过渡。
- 导航使用语义化链接或按钮，支持键盘操作，并确保移动端仍能访问全部板块。
- 内容区不依赖悬停才能读取；长标题、长摘要、窄屏文字不被裁切。

## 4. Alpha 信息架构

### 4.1 全局骨架

后续实现采用单页静态结构：

```text
┌──────────────────────┬───────────────────────────────────────┐
│ 品牌 / 个人标识       │ 右侧主内容区                           │
│ 六项导航              │ 关于我 → 学在南雍 → 玩在金陵 →          │
│ GitHub 入口           │ 南雍杂忆 → 文章检索 → GitHub            │
└──────────────────────┴───────────────────────────────────────┘
```

桌面端由左侧 `aside` 和右侧 `main` 构成；导航跳转到同页锚点，滚动时同步当前板块状态。移动端隐藏固定左栏，改为顶部品牌栏和可横向滚动的板块导航，保持 `MD_Demo` 的响应式方向。

### 4.2 关于我

定位为首屏入口，承担“我是谁、关注什么、如何继续了解”的信息。计划包含：

- 简短个人定位与一句自述。
- 头像或抽象 SVG 个人标识的占位。
- 一到两个低风险入口，例如查看文章、访问 GitHub。
- 不使用未经用户提供的姓名、学校身份、联系方式或经历。

### 4.3 学在南雍

定位为学习经历与思考的内容区。计划使用时间线、主题卡片或分组列表承载课程、阅读、项目、方法论等内容；具体条目由用户提供后再定稿。视觉上使用 `MD_Demo` 的容器蓝强调重要节点，正文保持画布白和文字墨。

### 4.4 玩在金陵

定位为南京城市生活与兴趣探索区。计划使用地点/路线/活动卡片，统一采用 SVG 地图或兴趣图标；地点描述、照片和推荐理由必须来自用户内容或明确标注为待补资料，不把常识性南京景点自动写成个人经历。

### 4.5 南雍杂忆

定位为碎片化记忆、短札或片段记录区。计划支持日期、标题、摘要和阅读入口；内容以轻量卡片或纵向记忆流呈现，避免过度装饰和编号化。

### 4.6 文章检索

定位为全站文章的静态检索入口。Alpha 采用前端本地数据，不建立后端接口：

- 文章元数据集中维护在静态 JS/JSON 数据中。
- 关键词匹配标题、摘要、标签和正文索引字段。
- 输入时显示结果数量；无结果时说明下一步，例如清空关键词或调整筛选。
- 文章详情可使用同页展开、锚点或静态独立页面；先根据文章数量选择最简单且可维护的方式。
- 如果加入标签筛选，筛选项只来自真实文章数据，不能预置虚假的分类内容。

### 4.7 GitHub

定位为外部连接区：

- 展示 GitHub 用户名、简介和个人主页链接的内容位。
- 以静态链接展示精选仓库或项目列表。
- Alpha 不强依赖实时 GitHub API，避免 API 限额、跨域和 GitHub Pages 访问不稳定；如未来需要实时数据，必须提供静态回退。
- GitHub 标识使用本地 SVG，沿用 `--ink` 体系，不另引入品牌色。

## 5. 后续实现方案

### 5.1 技术边界

- 首选原生 HTML、CSS、JavaScript，无框架、无构建步骤、无后端。
- 根目录保留 `index.html`，资源使用相对路径，兼容 GitHub Pages 的项目子路径。
- 不使用服务端路由；优先使用页面内锚点和必要的 hash 状态，确保刷新和直接访问链接可用。
- 不引入外部字体、图标 CDN 或运行时必须联网的依赖。

### 5.2 建议目录

```text
MyBlog/
├── index.html
├── assets/
│   ├── css/
│   │   ├── tokens.css       # 四色 Token、字号、间距、圆角
│   │   ├── layout.css       # 左右双栏、主内容和响应式骨架
│   │   └── components.css   # 卡片、按钮、输入、检索、状态
│   ├── js/
│   │   ├── app.js           # 导航、滚动状态和页面初始化
│   │   ├── content.js       # 可替换的个人内容与文章元数据
│   │   └── search.js        # 静态文章检索
│   └── icons.svg            # 统一 SVG symbol sprite
├── devlog/
│   └── alpha_plan.md
├── .gitignore
└── AGENTS.md                # 本地文件，已被忽略
```

目录只是 Alpha 的实现建议；开始写代码前，如果用户指定技术栈、现有素材或文件组织，以上方案以用户的新要求为准。

### 5.3 组件优先级

1. 全局 Token、左右双栏和响应式导航。
2. SVG 图标注册与可访问名称。
3. 关于我首屏和六个板块的语义结构。
4. 复用卡片、标签、按钮、时间线、文章列表等基础组件。
5. 本地文章检索、筛选、无结果状态。
6. 内容占位替换、链接校验和 GitHub 区块。
7. 视觉回归、可访问性检查和 GitHub Pages 交付说明。

## 9. 个人主页首页计划与实施记录

### 9.1 参考调研与取舍

本轮读取了几个真实的个人博客主页，用于提炼首页信息组织方式。调研只用于形成结构判断，不复制站点内容、品牌或代码：

1. [Paul Stamatiou](https://paulstamatiou.com/)：首页直接并列个人身份信息、文章列表、器材兴趣和照片入口。可借鉴“个人信息 + 内容入口”并置的结构，但本项目先收敛为个人信息卡片和文章精选，不加入照片墙。
2. [Maggie Appleton](https://maggieappleton.com/)：使用少量清晰的一级内容分类承载 Garden、Essays、Notes、Patterns 等不同内容。可借鉴分类入口的清晰度，避免为 MyBlog 提前增加过多栏目。
3. [Simon Willison’s Weblog](https://simonwillison.net/)：将 About、Subscribe、TILs、Tools 与 Entries、Links、Quotes、Notes 等内容入口分开，并提供站内搜索。可借鉴“功能入口与内容入口分离”的信息架构，文章检索后续再接入。
4. [Gwern.net](https://gwern.net/)：拥有非常强的主题分类、时间索引和文章目录，适合作为检索和长期知识库的参考；其信息密度较高，本项目首页不直接采用这种密集目录。
5. [Overreacted](https://overreacted.io/)：首页将个人博客标识与文章标题、日期、短摘要组成极简列表。可借鉴精选文章的直接呈现方式，但本项目先使用三张独立卡片，保留个人主页的空间感。

调研环境说明：项目要求的 `wmux browser` 命令在当前环境不可用，因此本轮改用网页访问工具读取上述公开主页；未因此修改项目代码。

## 14. 学期切换课程卡片分行渐入计划（2026-09-12）

### 14.1 需求解释与范围

本条需求中的“学在金陵”按当前页面结构解释为“学在南雍”中的学期切换。仅调整点击顶部学期按钮后的课程卡片过渡，不改变左侧站点导航、顶部学期按钮、页面背景、课程卡片内容、目录 JSON 或课程跳转逻辑。

当前问题：

1. 点击学期按钮时，`#content-root` 整体执行渐入，导致标题、切换按钮和课程卡片一起运动。
2. 现有过渡时长约 420ms，体感过快。
3. 课程卡片没有按网格行分组，而是同一时间全部出现，缺少阅读顺序。

目标效果：

1. 学期切换时，标题和顶部切换区保持稳定；只有课程卡片区域执行过渡。
2. 过渡主时长统一为 1000ms。
3. 卡片按视觉网格逐行展开：同一行同时出现，下一行稍后出现，不做逐卡片的随机或左右交错动画。

### 14.2 动效行为规格

- 学期切换的触发点为顶部 `[data-study-term]` 按钮点击或键盘激活。
- 切换按钮本身保留现有 Ripple，不把 Ripple 时长与卡片渐入绑定。
- `.content-view`、页面标题、`.section-tabs` 不添加或重新触发整体渐入。
- `.course-grid` 作为唯一过渡区域；课程卡片先处于轻微下移、低透明度状态，再回到正常位置和透明度。
- 每一行的卡片共享同一个开始时间；行与行之间使用固定延迟，建议为 140ms。
- 单张卡片动画时长为 1000ms，采用无明显回弹的平滑缓动；总时长由行数自然增加，不通过压缩单卡片时长来实现“快闪”。
- 同一学期重复点击当前按钮时不重复刷新课程卡片，也不重新播放动画。
- 在动画播放期间再次切换学期时，立即清理旧卡片的动画状态，并从当前新列表重新计算行号与延迟，避免旧动画残留。

### 14.3 实现计划

1. 将当前通用页面进入动画与学期切换解耦：页面路由切换仍可保留整体渐入，但学期按钮事件不再调用整体内容渐入。
2. 渲染课程卡片后读取每张卡片的实际 `offsetTop`，按相同的顶部位置归并为网格行；不写死三列或行数，以适配桌面端窗口宽度和后续课程数量变化。
3. 为卡片写入行序号或 CSS 自定义属性，例如 `--course-row`，由 CSS 统一计算 `animation-delay`。
4. 给课程卡片增加专用的进入类名和 `@keyframes`，不复用 Ripple 或 Markdown 阅读页的动画类名。
5. 在课程卡片区域替换完成后强制触发一次可控的重排，再添加进入类，确保每次学期切换都能稳定播放且不影响卡片布局。
6. 监听动画结束并清理进入类与临时行号属性，避免长期保留动画状态；动画过程中允许正常点击卡片，不阻塞用户操作。

### 14.4 可访问性与降级

- `prefers-reduced-motion: reduce` 下不播放 1000ms 的位移动画，改为短时透明度变化或直接显示课程卡片。
- 不依赖颜色变化表达卡片是否出现，确保键盘焦点、选中状态与老师/内容数量信息在动画前后保持可见。
- 无 JavaScript 动画能力或动画 API 不可用时，课程卡片正常显示，不影响学期切换和跳转。
- 不新增系统滚动条，不改变现有滚动区域和液态玻璃材质。

### 14.5 验收标准

1. 在“大一上”与“大一下”等有不同课程内容的学期之间切换时，标题和顶部切换区不发生整体淡入或位移。
2. 课程卡片区域的动画计算时长为 1000ms；每一行的延迟相同，后一行延迟大于前一行。
3. 同一行卡片同时出现，不能表现为一张接一张的随机顺序。
4. 连续快速切换学期后，页面不出现旧卡片、重复卡片或动画叠加。
5. 课程卡片仍可点击进入对应课程，Ripple 仍保持 1s 且不被卡片渐入替代。
