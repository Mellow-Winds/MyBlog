## 2.1 有符号整数

整数的表达自然绕不开负数，所以有时候第一位是用来提供“符号标记”的，这样的表达叫做**原码表示法**
### 原码表示法
- 最高位是符号位
- 存在的问题：
   1.有+0，-0，过于冗余
   2.减法的符号设计不好
   所以抛弃了😒

### 补码表示法
现在使用的表示法
特点：使用模运算来实现负数的表示
如：-3=9（mod 12），在mod12的体系下，二者可看成是等价的
（计算机中则是8位二进制数模运算系统（mod $2^8$)）

| 数字  | 表示         |
| --- | ---------- |
| 0   | `00000000` |
| 1   | `00000001` |
| -1  | `11111111` |

算法：一个负数的补码是对应正数补码的各位取反，再加上1
如
 4：      `00000100`
 -4:       `11111011+1`
       `=11111100`

这样我们就理解了为什么int的整数范围是$-2^{31}$到$2^{31}-1$
- 注意：这样的表示在某些操作会有溢出的风险，比如负数取绝对值，此时需要引入``long int``来帮忙

## 2.2 无符号整数
使用``unsigned int``：可以表达的范围就只限于正数$0$ ~ $2^{32} -1$

## 2.3 如果合在一起呢？
如果运算中同时有有符号和无符号整数，将会按无符号整数理解计算
比如-1和0(unsigned)的比较会是-1>0，因为此时-1被视作无符号的111111……处理了

## 2.4 一些小提示
### 2.4.1 ``sizeof``和``strlen``的处理

sizeof,strlen的返回值是unsigned
因此形如
```
if(strlen1 - strlen2 < 0)
```
这样的代码将永远不会成立，因为无符号整数不会减到比0还要小

所以用：
```
if(strlen1 < strlen2)
```
来实现会更好🤩~

### 2.4.2 `%u`的处理
用%u会变成unsigned类型：
```
int a=-1;
printf("%u",a);
```

会输出$2^{32} -1$

### 2.4.3 ``char``的字节问题
char类型的最大值是127，如果超了就会发生不好的事情......
```
char a=10000
```
a是多少？
a是16，因为10000的二进制最后表示是00010000，char只能截取最后的8个bit，从而只能得到a=16
## 2.5 位运算
### 2.5.1 &
a&b，当两个都是1，结果才是1
a=5:     0101
b=10:  0110
a&b:    0100
（区分a && b，这个是判断a，b是否非0的操作）

&1可以实现取出最后一位
&111可以取出后三位……以此类推

通过位运算实现算法的精简

注意：位运算警惕数值溢出

# 3.浮点数

float和double在表达小数的时候都会带有误差，但是double有更多的字节所以可以表达更精确的小数部分
float精度大概在小数点后5~6位左右，double则一般是15~16位左右

试试：
```
a=1.1f;
b=2.2f;
c=3.3f;
if(a + b ==c){printf("yes!");}
```
这样将不会输出yes
那如何保证可以正常运算？
看差的绝对值是否小于某个很小的数字比如10^-5 之类的可以部分做到（🧐聪明的人类

tips：最好不要用float算一些数字比较大的式子
