# 59：求两个数组的交集

## 题目

找出两个数组相同的部分，且结果不含重复元素。

---

## 正确解答 1：暴力嵌套遍历

我一开始的代码是遍历：

```java
import java.util.ArrayList;

public class IntersectionOfTwoArrays {
    public static int[] intersection(int[] nums1, int[] nums2) {
        ArrayList<Integer> result = new ArrayList<>();
        for (int i : nums1) {
            for (int j : nums2) {
                if (i == j) {
                    if (!result.contains(i)) {
                        result.add(i);
                    }
                }
            }
        }
        int[] arr = new int[result.size()];
        for (int i = 0; i < result.size(); i++) {
            arr[i] = result.get(i);
        }
        return arr;
    }
}
```

时间复杂度来到了惊人的 $O(n \cdot m \cdot k)$（竟然过了，也是神了）

### 🔍 深度分析：为什么是 $O(n \cdot m \cdot k)$？

这里有三层操作：

| 操作 | 时间复杂度 | 说明 |
|---|---|---|
| 外层 `for (int i : nums1)` | $O(n)$ | 遍历 nums1 |
| 内层 `for (int j : nums2)` | $O(m)$ | 对每个 nums1 元素遍历 nums2 |
| `result.contains(i)` | $O(k)$ | `ArrayList.contains` 是线性扫描！ |

`ArrayList.contains()` 不是 $O(1)$！它内部是一个 `for` 循环，逐个比较每个元素，因此每次调用是 $O(k)$，k 是当前结果列表的长度。三层叠加，最坏情况是 $O(n \cdot m \cdot k)$。

---

## 正确解答 2：HashSet 优化

```java
import java.util.HashSet;
import java.util.Set;

public class IntersectionOfTwoArrays {
    public static int[] intersection(int[] nums1, int[] nums2) {
        Set<Integer> set1 = new HashSet<>();
        for (int n : nums1) set1.add(n);

        Set<Integer> resSet = new HashSet<>();
        for (int n : nums2) {
            if (set1.contains(n)) {
                resSet.add(n);
            }
        }
        int[] arr = new int[resSet.size()];
        int j = 0;
        for (int i : resSet) arr[j++] = i;
        return arr;
    }
}
```

### 🔍 深度分析：HashSet 为什么快？

**核心原理：哈希表**

`HashSet` 底层是一张"哈希表"（hash table）。当你调用 `set.contains(x)` 时，它并不逐个扫描元素，而是：

1. 对 `x` 调用 `hashCode()` 方法，得到一个整数（哈希值）
2. 用这个哈希值直接计算出 `x` 应该存放在数组的哪个"桶"（bucket）里
3. 直接去那个桶里查找，通常只需要 $O(1)$ 时间

这就像：与其在图书馆一本一本地翻书找某本书（$O(n)$），不如直接用索引系统找到它所在的书架编号（$O(1)$）。

**两个 HashSet 的职责分工：**

```
set1   → 存放 nums1 的所有元素（用于快速查询 "x 在 nums1 里有吗？"）
resSet → 存放交集结果（天然去重，因为 Set 不允许重复元素）
```

**时间复杂度对比：**

| 版本 | 时间复杂度 | 空间复杂度 |
|---|---|---|
| 暴力嵌套 | $O(n \cdot m \cdot k)$ | $O(k)$ |
| HashSet | $O(n + m)$ | $O(n + k)$ |

用空间换时间，是算法优化中最常见的思路之一。

### ⚠️ 注意：HashSet 的输出顺序不保证

`HashSet` 内部按哈希值存储，**遍历顺序和插入顺序无关**。如果题目要求结果有序，需要改用 `TreeSet`（自动排序，但操作变为 $O(\log n)$）或者最后对结果排序。

# 60：是否为子序列

## 题目

给定字符串 s 和字符串 t，判断 s 是否为 t 的子序列。

子序列：在原序列中删除某些字母（可以不删），不改变剩余的字母的相对顺序生成的序列。s 和 t 都只包含小写字母。

```
输入: s=abc  t=ahbgdc  → 输出：true
输入: s=acb  t=ahbgdc  → 输出：false
输入: s=axc  t=ahbgdc  → 输出：false
```

---

## 解答：使用双指针

```java
public class IsSubsequence {
    public static boolean isSubsequence(String s, String t) {
        int i = 0, j = 0;
        // 核心：在访问 charAt 之前，必须保证索引小于 length
        while (i < s.length() && j < t.length()) {
            if (s.charAt(i) == t.charAt(j)) {
                i++; // 只有匹配了，s 的指针才前进一步
            }
            j++; // 无论是否匹配，t 的指针都要后移
        }
        // 最终状态：如果 i 走到了 s 的末尾（等于长度），说明全部匹配成功
        return i == s.length();
    }
}
```

### 🔍 深度分析：双指针的本质

**为什么这个思路是对的？**

子序列的定义要求：s 中的字符必须**按顺序**出现在 t 中，但中间可以跳过 t 的任意字符。双指针完美地模拟了这个过程：

- 指针 `i`：追踪"我已经匹配了 s 的前几个字符"
- 指针 `j`：追踪"我正在扫描 t 的第几个字符"

**逐步模拟 `s="abc"`, `t="ahbgdc"`：**

```
i=0(a)  j=0(a)  → 匹配！i→1, j→1
i=1(b)  j=1(h)  → 不匹配，j→2
i=1(b)  j=2(b)  → 匹配！i→2, j→3
i=2(c)  j=3(g)  → 不匹配，j→4
i=2(c)  j=4(d)  → 不匹配，j→5
i=2(c)  j=5(c)  → 匹配！i→3, j→6
循环结束：i=3 == s.length()=3 → true ✅
```

**为什么 `j` 无论如何都要后移？**

因为我们在 t 里找 s[i]，如果 t[j] 不是我们要找的字符，我们只能跳过它，继续往后看。t 里的每个字符只有一次机会被匹配。

**关键边界条件：**

```java
while (i < s.length() && j < t.length())
```

两个条件缺一不可：
- `i < s.length()`：如果 s 已经全部匹配完了（i 到头），可以提前结束
- `j < t.length()`：如果 t 已经扫描完了但 s 还没匹配完，也要停止（说明失败）

**时间与空间复杂度：**

- 时间：$O(n + m)$，其中 n = t.length()，m = s.length()。每个字符最多被访问一次。
- 空间：$O(1)$，只用了两个整数指针，不需要额外存储空间。

### 💡 进阶思考：如果有大量查询怎么办？

如果 t 固定，但要判断大量不同的 s（比如 10 万个），每次都从头扫 t 效率较低。这时可以对 t 预处理：

```java
// 预处理：对 t 中每个位置，记录每个字母下一次出现的位置
// 这样每次查询 s 只需 O(|s| * 26) 的预处理时间，查询变为 O(|s|)
```

这是"二分查找"或"索引预处理"的思路，适合 Follow-up 类问题。

# 62：完全数与亏数

## 题干

分别完成两个方法，判断输入的正整数是不是一个 perfect number 或 deficient number。

**`perfect number`（完全数）**：如果一个数的所有因数（除了自身）之和正好等于这个数，则它是完全数。比如 6 的因数有 1、2、3，加起来等于 6。

**`deficient number`（亏数）**：如果一个数的所有因数（除了自身）之和小于这个数，则它是亏数。比如 10 的因数有 1、2、5，加起来等于 8 < 10。

---

## 解答

```java
public class PerfectAndDeficientNumbers {

    public static boolean isPerfect(int posInt) {
        int sum = 0;
        for (int i = 1; i < posInt; i++) {
            if (posInt % i == 0) {
                sum += i;
            }
        }
        return sum == posInt;
    }

    public static boolean isDeficient(int posInt) {
        int sum = 0;
        for (int i = 1; i < posInt; i++) {
            if (posInt % i == 0) {
                sum += i;
            }
        }
        return sum < posInt;
    }
}
```

### 🔍 深度分析：这个解法有什么可以优化的？

**当前解法的复杂度：$O(n)$**

对于每个数 `posInt`，我们从 1 遍历到 `posInt - 1`，做了 n-1 次除法。当 `posInt` 很大时（比如 10 亿），这会非常慢。

**优化思路：$O(\sqrt{n})$ 的因数求和**

因数总是成对出现的！如果 `i` 是 `n` 的因数，那么 `n/i` 也必然是 `n` 的因数。所以我们只需要遍历到 $\sqrt{n}$：

```java
public static int sumOfDivisors(int posInt) {
    if (posInt == 1) return 0; // 1 没有除自身以外的因数
    int sum = 1; // 1 是任何数的因数
    for (int i = 2; i * i <= posInt; i++) {
        if (posInt % i == 0) {
            sum += i;
            if (i != posInt / i) {      // 避免平方根重复计算（如 9 的因数 3）
                sum += posInt / i;
            }
        }
    }
    return sum;
}

public static boolean isPerfect(int posInt) {
    return sumOfDivisors(posInt) == posInt;
}

public static boolean isDeficient(int posInt) {
    return sumOfDivisors(posInt) < posInt;
}
```

**效果对比（以 posInt = 1,000,000 为例）：**

| 方法 | 循环次数 | 时间复杂度 |
|---|---|---|
| 原始方法 | ~1,000,000 次 | $O(n)$ |
| 优化方法 | ~1,000 次 | $O(\sqrt{n})$ |

**一个数学知识点：完全数极其稀少**

已知的完全数：6, 28, 496, 8128, 33550336, ...

截至 2024 年，人类只发现了 51 个完全数，且全部是偶数（奇数完全数是否存在至今未知）。

### 💡 三种数的分类

根据因数和与本身的大小关系，所有正整数分为三类：

```
因数和 == n  →  完全数 (Perfect)：   6, 28, 496...
因数和 <  n  →  亏数   (Deficient)：  1, 2, 3, 4, 5, 7, 8, 9, 10...（大多数数都是亏数）
因数和 >  n  →  盈数   (Abundant)：   12, 18, 20, 24...
```

# 63：奇偶排序

## 题目

将数组中奇数排在前面，偶数排在后面，相对顺序不变。

---

## 解答：使用双数组 + `ArrayList`

```java
import java.util.ArrayList;

public class ReOrderArray {
    public int[] reOrder(int[] array) {
        ArrayList<Integer> odd = new ArrayList<>();
        ArrayList<Integer> even = new ArrayList<>();
        for (int i : array) {
            if (i % 2 == 0) {
                even.add(i);
            } else {
                odd.add(i);
            }
        }
        int[] result = new int[odd.size() + even.size()];
        for (int k = 0; k < odd.size(); k++) {
            result[k] = odd.get(k);
        }
        for (int k = odd.size(); k < odd.size() + even.size(); k++) {
            result[k] = even.get(k - odd.size());
        }
        return result;
    }
}
```

### 🔍 深度分析：这个方法的特点

**时间复杂度：$O(n)$**，整个数组只遍历了一遍（分类）+ 两次小遍历（写回），总体是线性的。

**空间复杂度：$O(n)$**，额外创建了两个 ArrayList 来存储奇数和偶数。

**这个方法的优点：稳定**

奇数之间的相对顺序不变，偶数之间的相对顺序也不变（因为我们按原顺序依次 `add`）。这叫做"稳定排序"的性质。

### 💡 可能有更好的方法吗？

**方案 B：双指针（不稳定，但 $O(1)$ 空间）**

类似快排的 partition 思路：左指针找偶数，右指针找奇数，然后交换。

```java
public int[] reOrderFast(int[] array) {
    int left = 0, right = array.length - 1;
    while (left < right) {
        while (left < right && array[left] % 2 != 0) left++;  // 找到左边的偶数
        while (left < right && array[right] % 2 == 0) right--; // 找到右边的奇数
        if (left < right) {
            int tmp = array[left];
            array[left] = array[right];
            array[right] = tmp;
        }
    }
    return array;
}
```

⚠️ **这个方案不稳定**：原始奇数的相对顺序会被打乱。

**方案 C：插入排序思想（稳定，$O(n^2)$ 时间）**

每遇到一个奇数，就把它"插入"到已排好的奇数区域末尾（通过逐步向前交换）。稳定但慢。

**结论：**

如果题目要求保持相对顺序，你的双 ArrayList 方案（方案 A）是正确且简洁的选择；如果不要求稳定且追求空间极致，用双指针（方案 B）。

# 58：小行星碰撞问题

## 题目

给定一个整数数组 `asteroids`，表示在同一行的小行星。对于数组中的每一个元素，其绝对值表示小行星的大小，正负表示小行星的移动方向（正表示向右移动，负表示向左移动）。每一颗小行星以相同的速度移动。

找出碰撞后剩下的所有小行星，结果保留原有顺序。

碰撞规则：两个小行星相互碰撞，较小的小行星会爆炸。如果两颗小行星大小相同，则两颗小行星都会爆炸。两颗移动方向相同的小行星，永远不会发生碰撞。

---

## 错误解答

我的第一次思路：从右向左检查是否会碰撞，然后去判断。

```java
import java.util.ArrayList;
import static java.lang.Math.abs;

public class Asteroid {
    public int[] asteroidCollision(int[] asteroids) {
        ArrayList<Integer> Asteroids = new ArrayList<>();
        for (int i : asteroids) {
            Asteroids.add(i);
        }
        //1.From last to first
        int last = Asteroids.size() - 1;
        int prev = Asteroids.size() - 2;
        while (last >= 1 && prev >= 0) {
            if (Asteroids.get(last) < 0 && Asteroids.get(prev) > 0) {
                if (abs(Asteroids.get(last)) > abs(Asteroids.get(prev))) {
                    Asteroids.remove(prev);
                } else if (abs(Asteroids.get(last)) < abs(Asteroids.get(prev))) {
                    Asteroids.remove(last);
                } else {
                    Asteroids.remove(last);
                    Asteroids.remove(prev);
                }
            }
            last--;
            prev--;
        }
        int[] result = new int[Asteroids.size()];
        for (int i = 0; i < Asteroids.size(); i++) {
            result[i] = Asteroids.get(i);
        }
        return result;
    }
}
```

**为什么错了？** 因为这样的话，可能出现碰完后继续碰撞的被忽略了。考虑 `[10, -5, -5]`，那么我的会输出的是 `[10, -5]`，但这是不对的！

### 🔍 深度分析：错误的根因

你的第一版错误在于"指针是单调递减的"——它每次循环无论发生什么都执行 `last--; prev--;`，这意味着**碰撞后，它不会回头检查新产生的"相邻对"是否也会碰撞**。

用 `[10, -5, -5]` 模拟：

```
初始：[10, -5, -5]，prev=1(→-5)，last=2(←-5)
第1步：prev=-5<0，不满足碰撞条件（需要 prev>0），指针左移
       → prev=0, last=1
第2步：prev=10>0，last=-5<0，满足碰撞条件
       abs(-5) < abs(10)，所以 -5 爆炸，移除 index=1
       结果：[10, -5]，但 last--; prev-- 继续执行
       → 第二个 -5 从来没和 10 碰撞过！❌
```

正确答案应该是 `[10]`：
- 第一个 `-5` 撞上 `10`，`-5` 爆炸 → `[10, -5]`
- 第二个 `-5` 再撞 `10`，`-5` 爆炸 → `[10]`

---

## 正确示范 1：反复扫描（do-while）

```java
import java.util.ArrayList;
import static java.lang.Math.abs;

public class Asteroid {
    public int[] asteroidCollision(int[] asteroids) {
        ArrayList<Integer> list = new ArrayList<>();
        for (int i : asteroids) {
            list.add(i);
        }

        boolean collisionOccurred;
        do {
            collisionOccurred = false;
            // 每次从后往前扫描
            int last = list.size() - 1;
            int prev = list.size() - 2;

            while (last >= 1 && prev >= 0) {
                // 碰撞条件：左边向右(>0)，右边向左(<0)
                if (list.get(prev) > 0 && list.get(last) < 0) {
                    collisionOccurred = true;
                    int leftVal = list.get(prev);
                    int rightVal = list.get(last);

                    if (abs(rightVal) > abs(leftVal)) {
                        list.remove(prev); // 左边的碎了
                    } else if (abs(rightVal) < abs(leftVal)) {
                        list.remove(last); // 右边的碎了
                    } else {
                        // 都碎了：注意要先删下标大的(last)，再删小的(prev)
                        list.remove(last);
                        list.remove(prev);
                    }
                    // 一旦发生碰撞，当前的指针位置已经乱了，必须跳出内层循环重新扫描
                    break;
                }
                last--;
                prev--;
            }
        } while (collisionOccurred); // 如果这一轮有撞碎的，下一轮可能还有新的碰撞

        // 转换回数组
        int[] result = new int[list.size()];
        for (int i = 0; i < list.size(); i++) {
            result[i] = list.get(i);
        }
        return result;
    }
}
```

此方法时间复杂度是 $O(n^2)$，非常之复杂。（与此同时，也过了）

### 🔍 深度分析：为什么是 $O(n^2)$？

最坏情况：每一轮外层 `do-while` 只消除一颗行星，然后重新扫描整个列表。

例如 `[1000, -1, -1, -1, ..., -1]`（999 个 -1 全都被吃掉），需要 999 次外层循环，每次内层扫描 $O(n)$，共 $O(n^2)$。

此外，`ArrayList.remove(index)` 本身也是 $O(n)$，因为删除中间元素需要把后面的元素全部向前移位。

---

## 正确示范 2：栈（最优解）

### 1. 为什么我们需要"栈（Stack）"思想？

在之前的尝试中，我们发现"多次扫描"虽然直观，但效率较低（每次碰撞都要重头再来）。在 Java 开发中，当我们遇到"后进入的元素会与之前的元素发生交互"（如括号匹配、消除游戏、撤销操作）时，栈（Stack）是最佳选择。只要当前元素的操作取决于上一个元素的状态，且可能产生连锁反应，就请想到栈。

### 2. `ArrayList` 模拟栈的碰撞逻辑

我们将 `ArrayList` 看作一个只在末尾操作的容器。与其反复扫描整个列表，不如**只扫一遍数组**，在进入容器前就解决战斗。

### 3. 解答

```java
import java.util.ArrayList;

public class Asteroid {
    public int[] asteroidCollision(int[] asteroids) {
        // 使用 ArrayList 模拟栈的功能
        ArrayList<Integer> stack = new ArrayList<>();

        for (int ast : asteroids) {
            // 默认这颗行星是"活着"的
            boolean alive = true;

            // 发生碰撞的唯一条件：栈顶行星向右(>0)，当前行星向左(<0)
            while (alive && ast < 0 && !stack.isEmpty() && stack.get(stack.size() - 1) > 0) {
                int top = stack.get(stack.size() - 1);
                if (Math.abs(ast) > Math.abs(top)) {
                    // 1. 当前行星更强大：栈顶行星爆炸（移除），当前行星继续向左撞
                    stack.remove(stack.size() - 1);
                } else if (Math.abs(ast) == Math.abs(top)) {
                    // 2. 势均力敌：双双爆炸
                    stack.remove(stack.size() - 1);
                    alive = false; // 当前行星也碎了
                } else {
                    // 3. 栈顶更强大：当前行星爆炸
                    alive = false;
                }
            }
            // 如果历经碰撞后行星依然"活着"，或者根本没发生碰撞，则入栈
            if (alive) {
                stack.add(ast);
            }
        }

        // 将结果转换为 int[] 数组以符合测试要求
        int[] result = new int[stack.size()];
        for (int i = 0; i < stack.size(); i++) {
            result[i] = stack.get(i);
        }
        return result;
    }
}
```

### 🔍 深度分析：为什么栈在这里是天然的选择？

**关键洞察：碰撞只发生在"最新入场的向右行星"和"当前向左行星"之间。**

这正是栈的"后进先出"（LIFO）特性发挥作用的场景：最后加入的向右行星，永远是第一个面对新来的向左行星的。

**`while` 循环实现连锁碰撞：**

以 `[-2, 10, -5, -5]` 为例：

```
处理 -2：stack 为空，无碰撞，直接入栈 → stack=[-2]
处理 10：栈顶是负数，不碰撞，直接入栈 → stack=[-2, 10]
处理 -5：
  栈顶=10>0，ast=-5<0，碰撞！abs(-5)<abs(10)，-5 爆炸，alive=false
  → stack=[-2, 10]（未变）
处理 -5：
  栈顶=10>0，ast=-5<0，碰撞！abs(-5)<abs(10)，-5 爆炸，alive=false
  → stack=[-2, 10]（未变）
最终：[-2, 10] ✅
```

再看 `[10, -10, -5]`：

```
处理 10 → stack=[10]
处理 -10：栈顶=10，abs相等，双双爆炸，alive=false → stack=[]
处理 -5：stack 为空，alive 为 true，直接入栈 → stack=[-5]
最终：[-5] ✅
```

**`while` 循环的四个退出条件：**

```java
while (alive && ast < 0 && !stack.isEmpty() && stack.get(stack.size() - 1) > 0)
```

| 退出条件 | 含义 |
|---|---|
| `!alive` | 当前行星已爆炸，不再继续碰撞 |
| `ast >= 0` | 当前行星向右，不会向左碰撞 |
| `stack.isEmpty()` | 栈为空，没有可以碰撞的对象 |
| `stack.top <= 0` | 栈顶行星向左，同向行星不碰撞 |

任意一个条件触发，while 退出。

### 4. 分析

| | 反复扫描 | 栈 |
|---|---|---|
| **时间复杂度** | $O(n^2)$ | $O(n)$：每颗行星最多入栈一次、出栈一次 |
| **空间稳定性** | 频繁 `remove` 导致数组位移 | 仅在末尾操作，性能损耗极小 |
| **代码逻辑** | 需要多层循环和 flag 标记 | 一个 `for` 加一个内部 `while` 搞定 |

### 5. 总结

- **碰撞判断**：只有 `(栈顶 > 0 && 当前 < 0)` 这一种情况会相撞。
- **逻辑闭环**：使用 `boolean alive` 标记当前行星的状态，是处理"连锁碰撞"最简洁的方式。
- **集合转换**：`ArrayList` 转 `int[]` 目前需要手动遍历（或者使用 Java 8 的 `Stream` API，但初学者建议先手动遍历以加深对索引的理解）。

## 🧠 思维模板：什么时候用栈？

栈（Stack）不只是一种数据结构，它是一种**"记忆最近状态、等待与未来相遇"**的编程思想。以下场景几乎可以无脑想到栈：

| 场景 | 经典题目 |
|---|---|
| 括号匹配 | 有效的括号 (LC 20) |
| 消除/碰撞 | 小行星碰撞 (LC 735)、删除相邻重复项 |
| 单调栈（找下一个更大/更小元素） | 每日温度 (LC 739)、接雨水 (LC 42) |
| 撤销操作 | 浏览器的后退功能 |
| 递归转迭代 | DFS 遍历树/图 |

记住：**"当你发现新来的元素需要和最近入场的元素'算账'时，就用栈。"**
