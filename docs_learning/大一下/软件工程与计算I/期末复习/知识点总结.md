## 1. `main`方法
### 1.1 四问`main`函数
1. `main`方法必须声明为`public static void`吗？
	是的，必须。
	
2. `main`方法的参数名必须是`args`吗？
	不是的，`args`是约定俗成者。可以是别的。
	
3.  一个类可以有多个`main`方法吗？
	具体而言，可以有多个`main`方法，通过 Java 的方法重载（Overload）机制，你可以在同一个类中写多个名为 `main` 的方法。但**作为 JVM 程序启动入口的 `main` 方法是唯一的**。
	
4. `main`方法可以返回`int`类型吗？
	不可以。必须返回`void`。


## 2. 异常处理
### 2.1 复习PPT的题目
```
关于 Java 中的异常处理，下列说法正确的是？ 
A. finally 块中的代码一定会执行，无论是否抛出了异常。 
B. 自定义异常类必须直接继承 Exception 类。 
C. try 块中只能有一个 catch 块来捕获异常。 
D. RuntimeException 是受检异常，必须在方法签名中声明或在方法中捕获。 
```

1. `finally`块中的代码一定会执行，无论是否抛出了异常。
	完全正确。除非前面有`System.exit()`
	
2. 自定义异常类必须直接继承 Exception 类。
	错误！首先不一定是直接继承，可以是间接继承。此外，如果想定义**运行时异常（Unchecked Exception）**，则**须继承 `RuntimeException`（或其子类）**。
	
3. try 块中只能有一个 catch 块来捕获异常：
	完全错误！可以有多个。
```
补充：
在编写多个 catch 块时必须严格遵守“先子类后父类”的顺序规范。如果将父类异常（如 Exception）放在前面的 catch 块，后面的子类异常（如 NullPointerException）就会被完全遮蔽（Shadowed），导致编译直接报错。
此外，Java 7 之后还引入了多重捕获（Multi-catch）语法，允许在一个 catch 块中用竖线分隔捕获多种平级异常，如 catch (IOException | SQLException e)。
```
4. RuntimeException 是受检异常，必须在方法签名中声明或在方法中捕获。 
	完全错误！不一定要被捕获。

### 2.2 关于`finally`的一些提示
当 `try` 块和 `finally` 块中同时出现 `return` 语句，或者在 `finally` 中修改了返回值，结果会非常具有迷惑性。
#### 考点 1：返回值被覆盖

```java
public static int test() {
    try {
        return 1;
    } finally {
        return 2; // finally 中的 return 会“吞掉” try 中的 return 和异常
    }
}
// 结果：返回 2
```

**执行时序是这样的：**
1. 执行 `try` 块中的 `return 1;`
2. 计算返回值（准备要返回的值），此时确定了 `1`
3. **将返回值暂存起来**（存在操作数栈或局部变量区），准备返回
4. **但在真正返回之前**，JVM 会先去执行 `finally` 块
5. `finally` 中执行 `return 2;` —— **重新设定了一个新的返回值**
6. 因为 `finally` 执行完后必须返回，而它自己又带了 `return`，所以这个新的返回值 `2` 覆盖了之前暂存的 `1`
7. 最终返回 `2`
#### 考点 2：基本数据类型 vs 引用数据类型的修改

- **基本数据类型**：
```java
public static int test() {
    int a = 10;
    try {
        return a; // 此时已经在栈中复制了返回值 10 并暂存
    } finally {
        a = 20;   // 修改了局部变量 a，但无法改变已经暂存的返回值
    }
}
// 结果：返回 10，同时a被修改为了20。
```

- **引用数据类型**：
```java
    public static StringBuilder test() {
        StringBuilder sb = new StringBuilder("Hello");
        try {
            return sb; // 暂存了对象的引用地址
        } finally {
            sb.append(" World"); // 通过地址修改了堆中对象的内容
        }
    }
    // 结果：返回内容为 "Hello World" 的 StringBuilder 对象
```

- **如果 `finally` 中对引用变量重新赋值呢？**
```java
StringBuilder sb = new StringBuilder("Hello");
try {
    return sb;
} finally {
    sb = new StringBuilder("World"); // 重新指向新对象
}
```
**结果：返回的还是 `"Hello"`**  
因为 `return` 时暂存的是旧对象地址，`finally` 中把 `sb` 指向了新对象，但暂存的返回值还是那个旧的地址，所以返回旧对象。  **除非** `finally` 里也写 `return sb;`，才会覆盖。

### 2.3 异常体系的四大内容
- **Throwable**：所有错误和异常的终极超类。
    
    - **Error（错误）**：JVM 级别严重的问题。程序通常**无法靠自身代码恢复**。
        
        - 区分 `StackOverflowError`（栈溢出，通常由无限递归引起）与 `OutOfMemoryError`（堆溢出，通常由大对象分配或内存泄漏引起）。这两个是 **Error**，而不是 Exception！
            
    - **Exception（异常）**：程序运行中可以预见并捕获处理的情况。
        
        - **受检异常（Checked Exception）**：直接继承自 `Exception`（除了 `RuntimeException` 及其子类）。编译期强制要求处理（`try-catch` 或 `throws`），如 `IOException`, `SQLException`。
            
        - **非受检异常（Unchecked/Runtime Exception）**：继承自 `RuntimeException`。编译期不强制要求处理，通常是代码逻辑漏洞，如 `NullPointerException`, `ClassCastException`。

## 4. 编程题
编写一个Java 程序，要求实现以下功能： 
1. 定义一个抽象类`Shape`，包含抽象方法`area ()`用于计算形状的面积。 
2. 创建两个子类`Circle`和`Rectangle`，分别实现`Shape`类。

```java
// 抽象父类
abstract class Shape {
    public abstract double area();
}

// 圆形子类
class Circle extends Shape {
    private double r; // 半径

    public Circle(double r) { this.r = r; }

    @Override               //记得Override!
    public double area() { return Math.PI * r * r; }
}

// 矩形子类
class Rectangle extends Shape {
    private double w, h; // 宽、高

    public Rectangle(double w, double h) {
        this.w = w;
        this.h = h;
    }

    @Override
    public double area() { return w * h; }
}

// 测试类
public class Main {
    public static void main(String[] args) {
        Shape c = new Circle(5);
        Shape res = new Rectangle(4, 6);
        System.out.println("Circle: " + c.area());
        System.out.println("Rectangle: " + res.area());
    }
}
```

顺势复习一下：
### 1. 抽象 (Abstraction) 

**如何实现：** 在 Java 中，我们使用 **`abstract`** 关键字来修饰类和方法。

- **类级别**：在 `class` 前加上 `abstract`，即 **`abstract class Shape`**。
- **方法级别**：在方法返回值前加上 `public abstract`，即 **`public abstract double area();`**。这个方法**没有大括号 `{}`，只有分号 `;`**。
- **注意**：子类需要覆写`@Override`父类的方法。
### 2. 封装 (Encapsulation) 
**如何实现：** 在 Java 中，我们通过访问权限修饰符 **`private`** 和 **构造方法** 来实现封装。

- **私有化属性**：属性前面加上 **`private`**（如 `private double r;`）。这意味着外部代码无法通过 `object.r = -5;` 这种手段直接修改它们。
    
- **暴露安全入口**：外部想要传入数据，必须通过类提供的**构造方法**（如 `public Circle(double r) { this.r = r; }`）。在构造方法内部，可以加入安全校验逻辑（例如判断半径是否大于 0），从而保护了对象内部数据的合法性。
### 3. 继承 (Inheritance) 

**如何实现：** 在 Java 中，使用 **`extends`** 关键字来建立类与类之间的父子关系。

- **建立联系**：代码中的 **`class Circle extends Shape`** 和 **`class Rectangle extends Shape`**，就是让圆形和矩形继承自 `Shape`。
- **实现效果**：通过 `extends`，子类自动获得了父类的身份。而方法如果不一样，则需要覆写。

### 4. 多态 (Polymorphism) 
**如何实现：** 多态在 Java 中是通过 **方法重写（Override）** 和 **父类引用指向子类对象** 共同配合实现的。
- **内核重写**：子类在实现父类的抽象方法时，必须保持方法名和参数完全一致，并在上方加上 **`@Override`** 注解
- **外表统一（父类引用指向子类对象）**：在 `main` 方法中：
```java
Shape c = new Circle(5);
```
等号左边的变量类型是父类 **`Shape`**（统一的外表），而等号右边实际创建出来的对象是子类 **`new Circle(5)`**（具体的内核）。
- **实现方法**：当执行 `c.area()` 时，虽然编译期间编译器只知道 `c` 是个 `Shape`，但运行时 JVM 顺着引用看，发现堆内存里实际是个 `Circle` 对象，于是就会自动去执行 `Circle` 类里重写的那个面积公式。这就是多态的最终实现。

多态实现：
- 重载（Overload） 同一个类中，编译时确定 
- 重写（Override） 子类和父类之间，运行时确定

## 5. 简答题
请解释 `==` 和 `equals()` 的区别，并写出以下代码的输出结果。
```java
String str1 = new String("Hello");
String str2 = "Hello";
System.out.println(str1 == str2);
System.out.println(str1.equals(str2));
```
#### 5.1 辨析
1. `==` 运算符（比较地址/基本类型值）
	- **对于基本数据类型**（如 `int`, `double`）：比较的是它们的**具体数值**是否相等。
	- **对于引用数据类型**（如 `String`, 自定义类）：比较的是对象在虚拟机中的**内存地址**。只有当两个引用指向堆内存中完全相同的同一个对象实例时，`==` 才会返回 `true`。
2. `equals()` 方法（比较内容）
	- **默认情况**：如果没有被重写，底层依然使用的是 `==`，即比较地址。
	- **核心改变（如 `String` 类）**：Java 的很多内置类（包括 `String`, `Integer`, `Date` 等）都**重写**了 `equals()` 方法，将其改造为**比较对象的内容**。只要两个字符串里面包含的字符序列一模一样，`equals()` 就会返回 `true`，而不管它们存在于内存的什么位置。
#### 5.2 结论
这一题：
```java
String str1 = new String("Hello");
String str2 = "Hello";
System.out.println(str1 == str2);//false
System.out.println(str1.equals(str2));//true
```

- 为什么 `str1 == str2` 是 `false`？
	1. **`str2 = "Hello"`**：这种方式叫做字面量声明。JVM 会先去内存的“字符串常量池（String Constant Pool）”中检查是否存在 `"Hello"`。如果有，就直接把地址赋给 `str2`；如果没有，就在常量池中创建一个。
	2. **`str1 = new String("Hello")`**：使用 `new` 关键字时，JVM 会在堆内存（Heap）中**强行开辟一块全新的独立空间**来存放这个字符串对象，并让 `str1` 指向它。
	3. 此时，`str1` 指向的是**堆内存中的新对象地址**，而 `str2` 指向的是**字符串常量池中的对象地址**。由于这是两块截然不同的内存空间，它们的地址不同，因此使用 `==` 比较的结果为 `false`。

- 为什么 `str1.equals(str2)` 是 `true`？
	因为 `String` 类重写了 `equals()` 方法。当调用 `str1.equals(str2)` 时，JVM 已经不再关心两者的内存地址了，而是会把两个字符串拆成字符数组（`['H', 'e', 'l', 'l', 'o']`），然后逐个字符去比对。因为两个字符串的内容一模一样，所以结果返回 `true`。

#### 5.3 扩展

1. 两个都用 `new String()` 创建
```java
String str1 = new String("Hello");
String str2 = new String("Hello");

System.out.println(str1 == str2);       // 结果：false
System.out.println(str1.equals(str2));  // 结果：true
```
- 只要代码中出现了两个 `new` 关键字，JVM 就会在堆内存中**强行开辟两块彼此独立**的内存空间。也就是说，`str1` 存放的是堆内存 A 地址，`str2` 存放的是堆内存 B 地址。由于是不同的地址，`==` 必定为 `false`；而它们内部存的值都是 `"Hello"`，所以 `equals()` 依然是 `true`。
    

2. 直接引用赋值（指向同一块地方）
```java
String str1 = new String("Hello");
String str3 = str1; // 把 str1 的地址直接复制给 str3

System.out.println(str1 == str3);       // 结果：true
System.out.println(str1.equals(str3));  // 结果：true
```
- **内核剖析**：`String str3 = str1;` 这行代码并没有创建任何新对象。它只是把 `str1` 里存放的内存地址，完完整整地复制了一份给了 `str3`。此时 `str1` 和 `str3` 指向的是堆内存中的同一个对象实例，地址完全相同，因此 `==` 的结果直接变成了 `true`。

3. 纯字面量拼接（编译期优化）
```java
String str4 = "Hello";
String str5 = "He" + "llo"; // 纯字符串常量直接拼接

System.out.println(str4 == str5);       // 结果：true
System.out.println(str4.equals(str5));  // 结果：true
```

- **内核剖析**：这个场景非常具有迷惑性。因为 `"He"` 和 `"llo"` 都是写死的字面量（常量），Java 编译器在编译期间非常智能，它会直接把这行代码优化计算为 `String str5 = "Hello";`。既然变成了字面量声明，JVM 就会让他们同时指向“字符串常量池”中的同一个 `"Hello"`，因此它们的内存地址完全一致，`==` 也是 `true`。

4. 包含变量的拼接（运行期动态创建）
```java
String str6 = "Hello";
String part1 = "He";
String str7 = part1 + "llo"; // 拼接中包含了变量 part1

System.out.println(str6 == str7);       // 结果：false
System.out.println(str6.equals(str7));  // 结果：true
```

- **内核剖析**：虽然 `str7` 最后的拼接结果内容也是 `"Hello"`，但因为拼接过程中引入了变量 `part1`，编译器在编译期间无法预知 `part1` 会不会改变。因此，Java 会在程序**运行期间**通过类似 `StringBuilder` 的机制动态动态地在堆内存中创建一个全新的字符串对象。既然是运行期在堆里新造的对象，它的地址就绝对不会等于常量池中 `str6` 的地址，所以 `==` 结果为 `false`。


## 6. Lambda演算
对以下每个 Lambda 表达式，进行逐步的 β-归约，并给出每一步的推导过程。
表达式 1：$(\lambda x. (\lambda y. x \, y) \, (\lambda z. z \, z)) \, (\lambda w. w)$
表达式 2：$(\lambda x. x \, y) \, z$

### Lambda演算的解法（$\beta 规约$）

标准的 Lambda 形式是：    **$$(\lambda2. \text{整个函数体})1$$**
1. **第一步（锁定目标）**：
    - **1** 是右边的参数（无论多长，当成一个整体，这里记为的是$1$）。
    - **2** 是最左边 $\lambda$ 紧跟的那个变量（这里是$2$）。
2. **第二步（代入替换）**：
    - 找到大括号里的“整个函数体”。
    - 把里面所有的$2$，全部擦掉，换成$1$。
3. **第三步（脱掉外壳）**：
    - 把最外层的 $\lambda 2$ 这一个小东西**彻底删掉**。
### Lambda演算的解法（$\alpha 规约$）
就是替换变量。
### Church Numerals
#### 1. 邱奇数（Church Numerals）的核心本质

在 $\lambda$ 演算中，没有任何内置的数字类型。阿隆佐·邱奇（Alonzo Church）提出：**用“函数的组合层数”来表示自然数**。

一个邱奇数是一个接收两个参数（一个函数 $f$ 和一个初始值 $x$）的最高阶函数。数字 $n$ 代表将函数 $f$ 连续作用于 $x$ 上 $n$ 次（《Introduction to Lambda Calculus》）。

其通用形式化定义为：

$$n = \lambda f. \lambda x. f^n\ x$$

#### 2. 基础数字的 $\lambda$ 表达式

以下是自然数在 $\lambda$ 演算中的标准编码：

- **ZERO ($0$)**：函数 $f$ 作用了 $0$ 次（即直接返回初始值 $x$）。
    
    $$\text{ZERO} = \lambda f. \lambda x. x$$
    
- **ONE ($1$)**：函数 $f$ 作用了 $1$ 次。
    
    $$\text{ONE} = \lambda f. \lambda x. f\ x$$
    
- **TWO ($2$)**：函数 $f$ 作用了 $2$ 次（即嵌套组合：$f(f(x))$）。
    
    $$\text{TWO} = \lambda f. \lambda x. f\ (f\ x)$$
    
- **THREE ($3$)**：函数 $f$ 作用了 $3$ 次。
    
    $$\text{THREE} = \lambda f. \lambda x. f\ (f\ (f\ x))$$
    

#### 3. 核心算术运算与 $\beta$ 规约推导

为了在这些数字上做运算，需要定义高阶算子。

##### ① 后继函数（SUCC）

- **定义**：$\text{SUCC} = \lambda n. \lambda f. \lambda x. f\ (n\ f\ x)$
    
    - _含义_：接收一个邱奇数 $n$，在其基础上再多调用一次 $f$。
        

###### 实例推导：$\text{SUCC}\ \text{ONE}$

我们将 $\text{ONE} = \lambda f. \lambda x. f\ x$ 带入 $\text{SUCC}$ 算子中进行 $\beta$ 规约：

1. **代入 $n$**：
    
    $$(\lambda n. \lambda f. \lambda x. f\ (n\ f\ x))\ (\lambda f. \lambda x. f\ x)$$
    
    $$\rightarrow \lambda f. \lambda x. f\ ((\lambda f. \lambda x. f\ x)\ f\ x)$$
    
2. **规约内部的 $(\lambda f. \lambda x. f\ x)\ f$**（用外层的 $f$ 替换内层的 $f$）：
    
    $$\rightarrow \lambda f. \lambda x. f\ ((\lambda x. f\ x)\ x)$$
    
3. **继续规约 $(\lambda x. f\ x)\ x$**（用外层的 $x$ 替换内层的 $x$）：
    
    $$\rightarrow \lambda f. \lambda x. f\ (f\ x)$$
    

最终结果为 $\lambda f. \lambda x. f\ (f\ x)$，这正是邱奇数 **TWO**。

##### ② 加法函数（PLUS）

- **定义**：$\text{PLUS} = \lambda m. \lambda n. \lambda f. \lambda x. m\ f\ (n\ f\ x)$
    
    - _含义_：先对 $x$ 调用 $n$ 次 $f$，再在此基础上调用 $m$ 次 $f$，总共调用 $m+n$ 次。
        

##### ③ 乘法函数（MULT）

- **定义**：$\text{MULT} = \lambda m. \lambda n. \lambda f. m\ (n\ f)$
    
    - _含义_：将“调用 $n$ 次 $f$ 的复合函数”作为一个整体，连续调用 $m$ 次，实现幂次级组合，总共调用 $m \times n$ 次（《Types and Programming Languages》）。

## 8. 面向对象题

### 1. 类的初始化顺序
当首次创建子类对象时，具体执行顺序如下：
1. **父类静态成员初始化与静态代码块**：按在代码中出现的先后顺序执行。
2. **子类静态成员初始化与静态代码块**：按在代码中出现的先后顺序执行。
3. **父类实例变量初始化与构造代码块**：按在代码中出现的先后顺序执行。
4. **父类构造器执行**。
5. **子类实例变量初始化与构造代码块**：按在代码中出现的先后顺序执行。
6. **子类构造器执行**。
### 2. 类的继承、封装与协作

- **封装（Encapsulation）**：隐藏对象的属性和实现细节，仅对外公开接口。通过控制访问级别（如 private、protected、public）来保证数据的安全性和完整性。
    
- **继承（Inheritance）**：子类继承父类的属性和方法，实现代码复用。支持“is-a”关系。
    
- **协作与扩展设计（向系统添加新功能）**：
    
    - 遵循**开闭原则（Open-Closed Principle）**：对扩展开放，对修改关闭。
        
    - 通过引入**抽象类（Abstract Class）** 或 **接口（Interface）** 定义行为规范。当需要添加新功能时，编写新的实现类，而不是修改现有的业务逻辑代码，结合**多态（Polymorphism）** 和 **工厂模式**等设计模式实现动态注入。
        

### 3. 类之间的关系

在面向对象设计（UML）中，类与类之间的关系按紧密程度由弱到强依次为：

- **依赖（Dependency）**：一种弱关系。一个类的方法操纵另一个类的对象（如作为方法参数、局部变量或返回值）。“Use-a”关系。
- **关联（Association）**：类之间存在长期的、结构化的关系。一个类的对象知道另一个类的对象（如作为成员变量）。“Has-a”关系。
- **聚合（Aggregation）**：一种特殊的关联，表示“整体-部分”关系，但部分可以离开整体而独立存在。例如：**图书馆（Library）和图书（Book）**，图书馆倒闭了，图书依然存在。
- **组合（Composition）**：强烈的“整体-部分”关系，部分的生命周期由整体控制，部分不能脱离整体而独立存在。例如：**图书（Book）和书页（Page）**，图书被销毁，书页也随之销毁。
    
- **继承/泛化（Inheritance/Generalization）**：父类与子类的关系。“Is-a”关系。
    
- **实现（Realization）**：接口与实现类的关系。
### 4. 类图
#### 1. 类的表示方式（矩形三层结构）

在 UML 中，一个类用一个**闭合的矩形**表示，矩形从上到下分为三层：
1. **第一层：类名**（Class Name）。如果是抽象类，类名用斜体表示；如果是接口，会在类名上方加 `<<interface>>`。
2. **第二层：属性**（Attributes/Fields）。
3. **第三层：方法**（Methods/Functions）。
##### 属性和方法的可见性修饰符

在属性和方法前面，要用符号表示它们的访问权限：
- `+` ：`public`（公有）
- `-` ：`private`（私有）
- `#` ：`protected`（受保护）
- `~` ：`package`（包内可见，较少用）
##### 标准书写格式
- **属性格式**：`权限 属性名: 类型 [= 默认值]` （例如：`- name: String`）
- **方法格式**：`权限 方法名(参数名: 参数类型): 返回值类型` （例如：`+ getName(): String`）
#### 2. 类与类之间的 6 种关系（核心难点）
在画类图时，连线的**箭头形状**和**虚实线**有着严密的逻辑含义。按耦合度从弱到强排列：
##### ① 依赖关系 (Dependency)
- **概念**：一个类利用了另一个类，通常表现为**局部变量、方法参数**或者对静态方法的调用。
- **图示**：**虚线 + 箭头** ($\dashrightarrow$)。箭头指向被依赖的类。
##### ② 关联关系 (Association)
- **概念**：类与类之间有固定的结构化连接，通常表现为**成员变量**。可以单向或双向，还可以标注多度性（如 `1`、`0..*` 表示数量）。
- **图示**：**实线 + 箭头** ($\rightarrow$)。箭头指向被拥有的类。
##### ③ 聚合关系 (Aggregation)
- **概念**：特殊的关联关系，表示“整体与部分”的关系，且**部分可以离开整体而独立存在**（弱拥有）。例如：图书馆和图书、公司和员工。
- **图示**：**空心菱形 + 实线 + 箭头** ($\diamond-\rightarrow$)。空心菱形位于“整体”一端。
##### ④ 组合关系 (Composition)
- **概念**：更强的“整体与部分”关系，**部分不能离开整体而独立存在**，它们的生命周期一致（强拥有）。例如：人与大脑、一本书与它的目录。
- **图示**：**实心菱形 + 实线 + 箭头** ($\blacklozenge-\rightarrow$)。实心菱形位于“整体”一端。
##### ⑤ 继承/泛化关系 (Generalization)
- **概念**：父类与子类的关系（`extends`）。
- **图示**：**实线 + 空心三角形箭头**（$\rightarrow$ 形状为指向父类的空心三角）。
##### ⑥ 实现关系 (Realization)
- **概念**：类与接口的关系（`implements`）。
- **图示**：**虚线 + 空心三角形箭头**。箭头指向接口。

### 5. 用例图
用例图主要用于**需求分析**阶段，从用户的角度来描述系统“能做什么”，而不关心系统内部是如何实现的 。
#### 核心组成要素

- **参与者 (Actor)**：系统外部与系统进行交互的人、外部系统或硬件设备，在图中通常用**小人**表示。
    
- **用例 (Use Case)**：系统为参与者提供的一项完整的功能或服务，在图中通常用**椭圆**表示。
    
- **系统边界 (System Boundary)**：用方框表示，代表系统的范围，将系统内部的用例与外部的参与者分隔开。
    
- **关系**：
    
    - **关联 (Association)**：参与者与用例之间的连线，表示交互。
        
    - **包含 ($\text{<<include>>}$)**：一个复杂用例包含了另一个基础用例。
        
    - **扩展 ($\text{<<extend>>}$)**：在特定条件下，某个用例会触发另一个可选的扩展功能。

## 8. JVM

### 一、 方法调用字节码指令：`invoke` 指令集

JVM 提供了 5 种不同的方法调用字节码指令，它们在底层决定了方法如何被定位和执行：

1. **`invokevirtual`（调用虚方法）**
    
    - **含义**：用于调用所有的**公共、受保护或默认访问权限的实例方法**（即普通非静态方法）。
        
    - **特点**：它是 Java **多态和动态绑定**的基石。在运行时，JVM 会根据对象的实际类型（实际引用）在方法表中进行动态查找并调用，而不是依赖编译期的声明类型。
        
2. **`invokespecial`（调用特殊方法）**
    
    - **含义**：用于调用不需要动态分派的特殊实例方法。
        
    - **范围**：包括类的**实例初始化方法（`<init>`，即构造器）**、**私有方法（`private`）** 以及**父类方法（通过 `super` 关键字显式调用）**。
        
    - **特点**：这些方法在编译期就完全确定了调用版本，运行时直接精确定位，不需要经过动态查找。
        
3. **`invokeinterface`（调用接口方法）**
    
    - **含义**：用于调用**接口中声明的方法**。
        
    - **特点**：在运行时会搜索一个实现了该接口的具体对象。由于一个类可以实现多个接口，接口方法在方法表中的索引（Offset）并不是固定的，因此 `invokeinterface` 的运行时性能通常略低于 `invokevirtual`，它需要更复杂的接口方法表（ITable）来动态检索。
        
4. **`invokestatic`（调用静态方法）**
    
    - **含义**：用于调用类的静态方法（`static`）。在编译期完全确定，属于静态绑定。
        
5. **`invokedynamic`（动态调用指令）**
    
    - **含义**：Java 7 引入、Java 8 成为 Lambda 表达式底层支柱的指令。它将方法分派的决定权从虚拟机转嫁给用户自定义的“引导方法”（Bootstrap Method），在运行期动态解析出调用点，是支持动态类型语言和 Lambda 表达式高效运行的关键。
        
- invokevirtual : 虚函数（正常的方法调用）
- invokespecial : 构造方法，父类方法，私有方法
- invokeinterface : 接口方法
- invokestatic : 静态方法
### 二、 分派原则：动态绑定与静态绑定

方法的调用在 JVM 底层分为**静态分派**和**动态分派**，这直接对应了编译期和运行期的行为：

#### 1. 静态分派（Static Dispatch）—— 对应 Overloading（方法重载）

- **定义**：发生在**编译期**。编译器在编译代码时，完全依赖方法调用者的静态类型（声明类型）来决定调用哪一个方法版本。
    
- **经典场景**：方法重载。
```java
    public void burn(Human h) { ... }
    public void burn(Man m) { ... }
    
    Human p = new Man();
    burn(p); // 编译期分配的是 burn(Human h) 版本，因为 p 的声明类型是 Human
```
#### 2. 动态分派（Dynamic Dispatch）—— 对应 Overriding（方法重写）

- **定义**：发生在**运行期**。JVM 在执行 `invokevirtual` 指令时，会先去推导调用者的**实际类型（隐式参数 `this` 对应的在堆中的实际对象类型）**，从而找到子类覆写后的方法版本。
    
- **核心原理**：**虚方法表（VTable）**。为了提高性能，JVM 会在类加载的准备阶段，为每个类在方法区建立一个虚方法表。如果子类没有重写父类的方法，子类 VTable 中该方法的地址指向父类；如果子类重写了，子类 VTable 中该方法的地址就会被替换为子类自身代码块的地址。
    

### 三、 核心基础字节码指令：操作数栈与局部变量表

执行一段简单的加法代码，在 JVM 内部是一个**基于栈的指令集架构**执行流。

#### 核心指令含义：

- **`iconst_<i>`**：将 `int` 类型的常量 `i` 压入操作数栈（Operand Stack）的栈顶。
- **`istore_<n>`**：将操作数栈顶的 `int` 类型数值弹出，并存入局部变量表（Local Variable Table）索引为 `n` 的插槽（Slot）中。
- **`iload_<n>`**：将局部变量表中索引为 `n` 的 `int` 类型数值复制出来，压入操作数栈顶。
- **`iadd`**：将操作数栈顶的两个 `int` 类型数值弹出，执行加法运算，然后将计算结果重新压入操作数栈顶。
#### 基本操作流程
1. 入栈 $\rightarrow$ `iconst_n`
	- **映射过程**：**入栈（将常量或数据压入操作数栈）**。
	- **指令行为**：`iconst_n`（或是针对更大常量的 `bipush` / `sipush`）专门负责把编译器知道的整型常量直接“推”到操作数栈的最顶部，作为计算的源头。
	
2. 存入 $\rightarrow$ `istore_x`
	- **映射过程**：**存入（从操作数栈弹出，写进局部变量表，完成变量赋值）**。
	- **指令行为**：`istore_x` 中的 `store` 就是存储的意思。它把刚刚压入栈顶的数据“拿出来”，塞进局部变量表的第 `x` 个格子里。这一步在 Java 语言层面就等价于完成了变量的赋值（如 `a = 1;`）。
	
3. 读取 $\rightarrow$ `iload_x`
	- **映射过程**：**读取（从局部变量表复制出来，重新压入操作数栈，准备计算）**。
	- **指令行为**：`iload_x` 中的 `load` 是加载的意思。当后面的代码需要用到某个变量（比如做加法）时，它会去局部变量表的第 `x` 个格子把值“复制”一份，然后重新塞回操作数栈里排队。
	
4. 计算并出栈 $\rightarrow$ `icalculate` (以 `iadd` 为例)
- **映射过程**：**计算并出栈（操作指令直接弹出栈顶的元素，在栈顶完成计算，再把结果压回栈顶）**。
- **指令行为**：以 `iadd` 为例，它不需要去局部变量表找数，它只认操作数栈。它会直接抓取栈顶最上层的两个数，让它们在物理层面完成加法，然后把最终的得数重新“按”回栈顶，等待下一步指令（比如下一个 `istore`）的调度.
#### 实例追踪：

对于代码 `int a = 1; int b = 2; int c = a + b;`，其底层的指令流转过程如下：

```java
[iconst_1]        ── 栈顶压入 1 ──> 操作数栈: [1]
[istore_1]        ── 弹出 1 存入局部变量表 Slot 1 ──> 局部变量表: [1: a=1]
[iconst_2]        ── 栈顶压入 2 ──> 操作数栈: [2]
[istore_2]        ── 弹出 2 存入局部变量表 Slot 2 ──> 局部变量表: [1: a=1, 2: b=2]
[iload_1]         ── 将 Slot 1 的 1 压栈 ──> 操作数栈: [1]
[iload_2]         ── 将 Slot 2 的 2 压栈 ──> 操作数栈: [1, 2]
[iadd]            ── 弹出 1 和 2 算加法，结果 3 压栈 ──> 操作数栈: [3]
[istore_3]        ── 弹出 3 存入局部变量表 Slot 3 ──> 局部变量表: [1: a=1, 2: b=2, 3: c=3]
```

### 四、 JVM 内存区域划分
变量在栈，对象在堆。

根据《Java虚拟机规范》，JVM 运行时数据区主要划分为以下三大核心板块（不含程序计数器与本地方法栈）：

#### 1. 堆区（Heap）

- **存储内容**：存放**所有的对象实例**以及**数组**。只要你写了 `new`，对象都在堆中分配。
    
- **生命周期与共享性**：**线程共享**。随着虚拟机的启动而创建，是垃圾回收器（GC）工作的主战场。
    

#### 2. 虚拟机栈区（JVM Stack）

- **存储内容**：每个方法被执行时，JVM 都会同步创建一个**栈帧（Stack Frame）**。栈帧中存放着**局部变量表**（基本数据类型、对象引用地址）、**操作数栈**、**动态连接**和**方法出口**。
    
- **生命周期与共享性**：**线程私有**。它的生命周期与具体线程绑定，方法调用开始则压栈，方法执行完毕则出栈。如果栈深度过深会引发 `StackOverflowError`。
    

#### 3. 方法区（Method Area / 现代元空间 Metaspace）

- **存储内容**：存放已被虚拟机加载的**类信息（Class 元数据）**、**常量**、**静态变量（`static`）**、以及即时编译器编译后的代码缓存。
    
- **特殊组件：运行时常量池（Runtime Constant Pool）**：属于方法区的一部分，存放编译期生成的各种字面量和符号引用（注意：字符串常量池在 Java 7 之后被移到了堆区中，但类的元数据常量池依然在方法区/元空间内）。
    
- **生命周期与共享性**：**线程共享**。
    

### 五、 Overloading（重载）与 Overriding（重写）的区别

|**特性**|**Overloading (方法重载)**|**Overriding (方法重写)**|
|---|---|---|
|**定义**|在**同一个类**中，方法名相同，参数列表不同。|在**子类**中，重写**父类**已有的、且有访问权限的方法。|
|**参数列表**|**必须不同**（参数个数、类型或顺序不同）。|**必须完全相同**。|
|**返回值类型**|可以相同，也可以不同。|必须与父类相同，或是父类返回类型的**子类（协变返回）**。|
|**异常抛出**|可以抛出任何异常，没有限制。|不能抛出比父类**更大、更通用**的受检异常。|
|**绑定机制**|**静态绑定**（静态分派，编译期根据声明类型确定）。|**动态绑定**（动态分派，运行期根据对象实际类型确定）。|
|**字节码指令**|通常解析为 `invokestatic` 或 `invokevirtual` 早期版本。|严格通过 `invokevirtual` 或 `invokeinterface` 动态寻找。|
