## Java 文件读取核心：BufferedReader 与 Try-with-resources

### 1. 为什么用 BufferedReader？

- **底层逻辑**：硬盘读取速度远慢于内存。如果程序每读一个字节都去访问一次硬盘，性能会非常糟糕。
    
- **应用场景**：`BufferedReader` 会预先读取一大块数据放入缓冲区（Buffer），程序直接从缓冲区拿数据，就像从水缸里舀水，而不是去井里一滴滴打水。
    

### 2. 为什么用 Try-with-resources？

- **底层逻辑**：文件流属于操作系统的外部资源。Java 虚拟机无法自动回收它们。如果不手动关闭，就会造成“内存泄漏”。
    
- **便捷性**：在 `try()` 括号内声明的资源，在代码块执行结束（无论是否报错）后，Java 会**自动调用** `close()` 方法。
    

### 3. 代码示范：读取玩家名单

假设我们有一个 `players.txt` 文件，里面每行写着一个 Minecraft 玩家的名字，我们要把它读出来。
```java
import java.io.BufferedReader;
import java.io.IOException;
import java.nio.file.Files;
import java.nio.file.Paths;
import java.util.ArrayList;
import java.util.List;

public class FileReadExample {
    public static void main(String[] args) {
        // 文件路径（假设在项目根目录）
        String filePath = "players.txt"; 
        List<String> playerList = new ArrayList<>();

        // 1. try-with-resources: 括号里的资源会自动关闭
        try (BufferedReader reader = Files.newBufferedReader(Paths.get(filePath))) {
            String line;
            // 2. 循环读取：只要 readLine() 没返回 null，就一直读
            while ((line = reader.readLine()) != null) {
                playerList.add(line); // 把读取的一行（玩家名）存入列表
            }
            
            // 3. 边界检查：展示 1-indexed (人类习惯) 到 0-indexed (代码习惯) 的转换
            if (!playerList.isEmpty()) {
                System.out.println("第一位玩家是: " + playerList.get(0)); // 程序员数 0，其实是第 1 个
            }

        } catch (IOException e) {
            // 处理文件不存在或读取出错的情况
            System.err.println("读取文件时出错了: " + e.getMessage());
        }
    }
}
```

### 💡 知识点总结
1. **Paths.get()** 定位文件。
2. **Files.newBufferedReader()** 开启高效读取通道。
3. **readLine() == null** 是停止读取的信号。
4. **try(...)** 帮你“随手关门”。

## Java 文件写入进阶：BufferedWriter 与多资源管理

### 1. 写入模式的“开关”：StandardOpenOption

在 Java 中，我们通过 `Files.newBufferedWriter` 的可选参数来决定“怎么写”：

- **覆盖模式 (默认)**：不传参数，或者传 `StandardOpenOption.CREATE`。如果文件存在，内容会被清空。
    
- **追加模式**：传 `StandardOpenOption.APPEND`。内容会写在文件末尾。
    
- **自动创建**：配合 `StandardOpenOption.CREATE` 使用，如果文件不存在，Java 会帮你新建一个。
    

### 2. 为什么需要多资源管理？

**底层逻辑**：在处理数据时，我们经常需要“边读边写”。
**实现方式**：在 `try` 的括号里，我们可以用**分号**分隔多个流，Java 会按照“后打开先关闭”的顺序自动处理它们。
### 3. 代码示范：Minecraft 登录日志记录器
我们要实现一个功能：读取 `players.txt`，将玩家名字读出来，打上时间戳，然后**追加**写入到 `server_log.txt` 中。
```java
import java.io.BufferedReader;
import java.io.BufferedWriter;
import java.io.IOException;
import java.nio.file.Files;
import java.nio.file.Paths;
import java.nio.file.StandardOpenOption;
import java.time.LocalDateTime;

public class MinecraftLogger {
    public static void main(String[] args) {
        // 定义输入和输出路径
        String inputPath = "players.txt";
        String outputPath = "server_log.txt";

        // try-with-resources 同时管理两个流：reader 和 writer
        // 注意中间用分号 ; 隔开
        try (
            BufferedReader reader = Files.newBufferedReader(Paths.get(inputPath));
            BufferedWriter writer = Files.newBufferedWriter(
                Paths.get(outputPath), 
                StandardOpenOption.CREATE, // 如果文件不存在则创建
                StandardOpenOption.APPEND  // 在末尾追加内容
            )
        ) {
            String line;
            while ((line = reader.readLine()) != null) {
                // 获取当前时间戳
                String time = LocalDateTime.now().toString();
                String logEntry = "[" + time + "] 玩家 " + line + " 加入了服务器";

                // 写入数据
                writer.write(logEntry);
                // 关键点：BufferedWriter 不会自动换行，必须手动调用 newLine()
                writer.newLine(); 
            }
            
            System.out.println("日志记录完成！");

        } catch (IOException e) {
            System.err.println("处理文件时出错: " + e.getMessage());
        }
    }
}
```

### 💡 知识点总结

1. **StandardOpenOption.APPEND**：是保护旧数据的关键。
    
2. **writer.newLine()**：`write()` 方法不会自动换行，不加这句的话，所有数据会挤在同一行。
    
3. **try-with-resources 多流管理**：`try (R1; R2) { ... }` 这种写法既简洁又安全。
